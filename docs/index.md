## Concept

- [Agent, release, and TestFlight workflow](concepts/agent-release-and-testflight-workflow.md): Repository agents use the ontology for durable context and structured Build reports for current state.
- [App Store host integration](concepts/app-store-host-integration.md): Apple-platform host integration remains private, sandbox-safe, and App Store compatible.
- [App-hosted build and packaging](concepts/app-hosted-build-and-packaging.md): The product packages upstream Linux as a Mach-O-native OrlixKernel framework and hosts execution through the native application without redefining Linux semantics.
- [Apple Platform UI Split Pattern (Spec)](concepts/apple-platform-ui-ownership.md): Apple Platform UI Split Pattern (Spec).
- [Boot and device trees](concepts/boot-and-device-trees.md): Boot remains bootloader-shaped.
- [Component ownership](concepts/component-ownership.md): OrlixKernel owns the Linux port, OrlixMLibC owns libc sysdeps, OrlixHostAdapter owns private Apple host mechanics, OrlixOS owns distribution and the app-facing session surface, and the native app owns presentation.
- [Console and terminal](concepts/console-and-terminal.md): Linux console selection and terminal application presentation are separate responsibilities.
- [Durable and generated trees](concepts/durable-and-generated-trees.md): Durable port inputs live in source overlays, configurations, and patches.
- [Hosted ELF and TCTI safety](concepts/hosted-elf-and-tcti-safety.md): Hosted Linux ELF execution preserves Linux process and ABI semantics while TCTI enforces translated execution constraints required by Apple platforms.
- [Lifecycle and namespaces](concepts/lifecycle-and-namespaces.md): One upstream Linux kernel may host isolated local instances using Linux namespaces and cgroups.
- [Native app and Herdr topology](concepts/native-app-and-herdr-topology.md): The native app owns Apple presentation and Herdr is authoritative for terminal panes, tabs, focus, and topology.
- [OCI and Docker compatibility](concepts/oci-and-docker-compatibility.md): OCI and Docker behavior is built from upstream Linux namespaces, cgroups, networking, storage, process, and lifecycle interfaces.
- [Orlix domain language](concepts/domain-language.md): Canonical terms follow component ownership: OrlixKernel is Linux, OrlixMLibC is libc, OrlixHostAdapter is private Apple integration, OrlixOS is the Kit and distribution, and Orlix is the native product application.
- [Profiles, ABI, and destination parity](concepts/profiles-abi-and-destination-parity.md): Release and development profiles may differ in diagnostics, but their Linux UAPI, package ABI, device shape, and userspace contract remain invariant across supported destinations.
- [Root storage, packages, and execution](concepts/root-storage-packages-and-execution.md): OrlixOS assembles curated root filesystems and packages.
- [Runtime proof promotion](concepts/runtime-proof-promotion.md): Runtime claims advance in order from kernel dependency proof through kselftest, libc, syscall and UAPI proof, a POSIX shell environment, then jq, curl, and zsh.
- [SFTP Files Feature-First Refactor (Spec)](concepts/feature-first-application-structure.md): SFTP Files Feature-First Refactor (Spec).
- [Upstream Linux ownership](concepts/upstream-linux-ownership.md): Linux owns Linux behavior, including VFS, tasks, signals, process lifecycle, namespaces, sockets, syscalls, exec, and interpreter behavior.
- [Virtio device model](concepts/virtio-device-model.md): Host-provided device services use upstream virtio classes where they fit.
